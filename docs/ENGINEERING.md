# Engineering setup and workflow

This is a public working repository. Detailed project notes are inside `docs/`; there is deliberately no root README.

## Baseline at 2026-10-14

- Expo SDK **57** (stable family); React Native **0.86.3**; React **19.2.3**.
- Expo SQLite, Expo Crypto, React DOM and SDK-pinned Reanimated/Worklets are direct dependencies; React DOM/Worklets pins prevent npm peer drift.
- TypeScript **strict**.
- Node.js **22.13+** required by the SDK; Node 24 LTS is recommended for development.
- Android is first; iOS requires macOS/Xcode for native builds.
- Dependency versions must be **SDK-compatible**, not simply the newest major versions from npm.
- Expo SDK 58 prereleases are not part of the baseline.

Sources: https://docs.expo.dev/versions/latest/ and https://docs.expo.dev/router/installation/

## Dependency workflow

1. Introduce only packages directly needed by active work.
2. Use `npx expo install <package>` for Expo/native dependencies so Expo selects compatible versions.
3. Run `npx expo install --check` after every dependency edit.
4. Lock resolved packages with `package-lock.json` once an online install is available.
5. Verify license, maintenance, changelog and native build impact before adopting new packages.
6. Do not bulk-upgrade Expo or React Native independently from the Expo version matrix.

Already installed: Expo SQLite, Crypto, Notifications, FileSystem, DocumentPicker, Sharing, SystemUI, Reanimated and Worklets. Not installed: Drizzle, rich note editor, haptics, gesture-handler or native widgets.

Also installed for the native planning/Studio pass: SDK-compatible DateTimePicker 9.1.0 (MIT), SplashScreen ~57.0.10 (MIT), SVG 15.15.4 (MIT) and Lucide React Native 1.57.0 (ISC). Import individual icons through public `lucide-react-native/icons/*` exports; importing the whole icon index inflated the sampled mobile bundle. Native additions require rebuilding the installed binary.

## Verification steps for each implementation

- Review the diff for accidental secrets, unrelated edits, stale placeholders or unnecessary abstractions.
- Run static TypeScript checks and Expo dependency compatibility checks.
- Run deterministic tests for changed domain logic.
- Test new navigation/gesture behaviors on Android; save evidence for UI changes.
- Update [ROADMAP.md](ROADMAP.md) in the same commit with the real result.
- Commit to `main` only when scope is coherent and verification status is stated.

## Troubleshooting

If SDK packages are mismatched, check `npx expo install --check` before forcing npm overrides. If a native library needs a development build, follow its config-plugin instructions and regenerate native projects intentionally; do not blindly edit generated Android/iOS files.

## Automated test budget

- Maximum **20** unique, focused test cases across all test files; current count: **20**.
- CI and `npm run test:domain` run `scripts/check-test-budget.mjs`.
- Prioritize date semantics, SQLite integrity and primary planning workflows.
- Review and replace stale cases before adding tests. Never generate broad redundant regression suites.
- Typechecking, Expo dependency validation and Metro bundling are not extra test cases.

## Standalone QA and release boundary

- Set `EVRIDA_BUILD_VARIANT=qa` when generating the native project to use a separate QA name, scheme and identifier. This preserves the primary app's database. `eas.json` also provides internal preview, iOS simulator and production build profiles.
- On Windows, generate Android with `npx expo prebuild --platform android --no-install`; build with `android/gradlew.bat app:assembleRelease --max-workers=2 -PreactNativeArchitectures=x86_64,arm64-v8a`. PowerShell must quote that comma-containing architecture argument.
- Generated local release APKs currently use Expo's debug signing configuration. They are standalone QA artifacts, not Play/App Store submissions. Production signing credentials and publisher metadata are not configured by this work.
- After QA generation, regenerate without the QA environment variable before the ordinary primary-app development workflow. Keep Metro processes for other projects intact.
- `npm run bundle:ios` verifies the shared iOS JavaScript/Hermes bundle. Linux CI can generate both native projects; Windows cannot produce or validate an Xcode archive. Native iOS remains a separate gate.
- Android 35 emulator samples include offline embedded-bundle launch, native file restoration, full Gboard capture, dirty draft close, time editing, light/dark, 130% Plan/horizon controls and a one-minute background notification. Physical-device timing/idle, screen readers and Apple runtime remain unverified.

## Dependency audit — 2026-10-15

Current `npm audit` reports 22 affected entries (19 high, 3 moderate), rooted in three advisories. This is not a clean-audit claim:

- `braces` and `node-forge` are transitive tooling dependencies with no newer patched release available at this check. They were absent from the inspected Android release source map. Their remaining build/tooling exposure is not eliminated by that runtime observation.
- `decode-uri-component` is included through Router/query-string. A malformed/oversized native-path guard rejects hostile percent encoding before tolerant decoding. This reduces that entry-point exposure; it does not remove the vulnerable transitive package. Its newer ESM-only major cannot be blindly substituted into the current CommonJS consumer.
- Override only `xcode`'s `uuid` to 11.1.1; the native project UUID generator was exercised successfully. Do not use `npm audit fix --force` to downgrade Expo/RN or introduce incompatible native versions.

Source advisories: https://github.com/advisories/GHSA-vfj7-8cjw-p6xm and https://github.com/advisories/GHSA-86w9-cpqp-85rv. Track upstream SDK-compatible fixes and re-evaluate before store release.

## 2026-10-15 — Android SQLite native-lifetime mitigation (not release acceptance)

Expo issues [#48999](https://github.com/expo/expo/issues/48999) and [#48995](https://github.com/expo/expo/issues/48995) document C++ statement/database lifetime and concurrency hazards, including SIGSEGVs involving `pthread_mutex_lock`. They resemble the earlier Evrida crash but do not establish identical root cause. Evrida uses Expo SQLite 57.0.4; a release-note fix for per-statement locking does not mean runtime teardown has been fully proven safe.

All seven UI/Focus consumers now receive `serializeDatabase(useSQLiteContext())` via `src/storage/use-database.ts`. The pure gate serializes `getFirstAsync`, `getAllAsync`, `runAsync`, `execAsync` and full exclusive transactions per native handle. Each exclusive callback receives an independently gated transaction object, and startup initialization remains on SQLiteProvider's original connection. Do not use the raw provider hook from feature code or call back into the parent database object from inside its own guarded exclusive transaction: that can deadlock the queue.

A JS serialization gate cannot prevent an independent native GC/teardown use-after-free; issue [#2](https://github.com/Nishef1/Eonward/issues/2) remains a **P0 release blocker**. Run physical/emulator lifecycle stress and capture logcat tombstones before considering an SDK upgrade or native patch. Do not silently mask connection errors with destructive database replacement or resets.

## 2026-10-15 — Native acceptance toolchain

`src/features/shell/AppDock.tsx` was still accessing the raw `useSQLiteContext` hook, bypassing the shared per-handle serial gate. It now uses `useEvridaDatabase`. The `scripts/check-database-access.mjs` CI guard rejects future occurrences outside the one canonical storage hook. Keep the code guard simple; it does not prove native garbage-collection safety.

The original dynamic QA app config (`app.config.js`) already separates production and QA bundle identifiers. Instead of duplicating it, `eas.json` now adds a credentials-free `e2e-test` profile and `scripts/check-qa-config.mjs` verifies those IDs in App checks. Android/iOS Maestro smoke definitions are in `.eas/workflows/native-smoke.yml`; the opt-in emulator-only Android lifecycle script is `scripts/android-sqlite-stress.sh`. See [NATIVE_ACCEPTANCE.md](NATIVE_ACCEPTANCE.md).

These are **test assets**, not recorded test outcomes. An EAS login/link is required to run the native workflow; there is no app signing, Play/App Store upload or native runtime assertion from the JS export checks. For Expo SQLite Android teardown / double-close reports, see Expo issue #48999; our P0 #2 remains open.
